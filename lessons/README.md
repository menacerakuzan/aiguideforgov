# Повні уроки — формат і статус

Тут лежить **фінальний контент кожного уроку** — той текст, промпти й матеріали, що
підуть на платформу дослівно. Це наступний рівень деталізації після [`../lessons.md`](../lessons.md)
(там — техзавдання «про що урок», тут — сам урок).

- Архітектура курсу — [`../plan.md`](../plan.md)
- Поурочне ТЗ — [`../lessons.md`](../lessons.md)
- Реалізація структури в базі — `../prisma/src/seed.ts`
- **Повний контент — цей каталог** → далі переноситься в `content/lessons-module-*.ts`

---

## Структура каталогу

```
lessons/
  README.md                    ← цей файл: формат + статус
  rozdil-1-osnovy/
    1.1-demonstratsiia.md
    1.2-shcho-take-shi.md
    ...
  rozdil-2-dokumenty/
    ...
```

Один файл = один урок. Назва файлу: `<модуль>.<урок>-<короткий-слаг>.md`.

---

## Як влаштований файл уроку

Кожен файл має **три зони**, чітко розділені:

| Зона | Заголовок | Для кого | Іде на платформу? |
|---|---|---|---|
| 🎯 Для розробника | `## 🎯 Для розробника` | Автор / програміст / методист | ❌ Ні |
| 📄 Контент уроку | `## 📄 Контент уроку` | Слухач бачить дослівно | ✅ Так |
| 🛠 Виробництво | `## 🛠 Матеріали для виробництва` | Хто знімає скрінкасти й робить графіку | ❌ Ні |

**Золоте правило:** усе, що під `## 📄 Контент уроку`, написане мовою слухача і не
містить методичних поміток («Мета:», «У бібліотеку»). Усе службове — у зонах 🎯 і 🛠.

## Блоки контенту (як мапиться на платформу)

Платформа рендерить урок із масиву `LessonBlock` (див. `packages/types/src/domain.ts`).
У зоні `## 📄 Контент уроку` кожен фрагмент позначений тегом блоку, щоб програміст
переніс його один-в-один:

| Тег у файлі | Тип блоку | Що це на екрані |
|---|---|---|
| `[text]` | `text` (html) | Абзаци, списки, заголовки, врізки, цитати |
| `[video]` | `video` (url, caption) | Відео / скрінкаст із підписом |
| `[pair]` | `pair` (danger / safe) | Порівняння «до / після» двома колонками |
| `[trafficLight]` | `trafficLight` (3 категорії) | Світлофор даних: 3 картки з прикладами |
| `[redact]` | `redact` | Інтерактив знеособлення: клікаєш чутливі фрагменти |
| `[check]` | `check` | Питання мікроперевірки з поясненням відповіді |
| `[prompt]` | (частина `text`) | Блок промпту з кнопкою «Копіювати» — рендериться як `<pre>` з кнопкою |

> `[prompt]` окремого типу в схемі поки немає — на платформі це `text`-блок зі
> спеціальною версткою (моноширинний блок + кнопки «Копіювати» / «Зберегти»).
> Якщо вирішимо зробити його окремим типом блоку — це маленька правка схеми; поки
> що програміст загортає його як `<pre class="prompt">…</pre>` усередині `text`.

## Домовленості про контент

1. **Мова слухача — проста.** Жодного терміна без пояснення тут же, у дужках.
2. **Звертання на «ви», доброзичливо, без зверхності.** Слухач — доросла зайнята людина,
   яка вперше відкрила ШІ. Не «як усі знають», а «зараз покажемо крок за кроком».
3. **Приклади — реальні канцелярські** (звернення, службова записка, лист), ніколи не
   «напиши вірш».
4. **Дані у прикладах завжди знеособлені.** Ім'я «Заявник», адреса «вул. N» тощо.
5. **Кожен промпт — робочий і самодостатній**, із плейсхолдерами у `[КВАДРАТНИХ ДУЖКАХ]`.
6. **Скрінкаст ніколи не єдиний носій:** усе, що у відео, продубльовано текстом і
   скріншотами (правило дублювання з plan.md §4).
7. **Довжина уроку 7–12 хв.** Якщо більше — ділимо.

## Порядок роботи

1. Пишемо урок у `.md` за форматом вище.
2. Погоджуємо (тон, глибина, довжина).
3. Програміст переносить зони `📄` у `content/lessons-module-*.ts` як `LessonBlock[]`.
4. Виробництво знімає скрінкасти й робить графіку за зоною `🛠`.
5. Юрист рецензує уроки з позначкою ⚖️ у зоні 🎯.
