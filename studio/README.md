# Виробництво медіа для уроків

Відео й скріншоти для уроків знімає скрипт, а не людина. Сценарій кожного ролика вже
написаний у самому уроці — зона `## 🛠 Матеріали для виробництва` у
[`../lessons/rozdil-1-osnovy/`](../lessons/rozdil-1-osnovy/).

> **Стандарт відео — [`STANDARD.md`](STANDARD.md).** Там принципи озвучки, правила кадру,
> перелік перевірених пасток і обов'язкова перевірка якості. Новий урок починається з
> нього, а не з цього файлу: тут про запуск оснастки, там про те, яким має вийти ролик.

> Знімаємо **на Windows** — свідомо. Глядач курсу працює у Windows, і в кадрі має бути
> той провідник, той діалог «Відкрити файл» і те перетягування, які він бачить щодня.
> Знята на Linux демонстрація виглядала б чужою саме для тих, кого ми вчимо.

## Розподіл ролей

| Шар | Чим | Навіщо |
|---|---|---|
| Розвідка | Playwright **MCP** | подивитись живий Gemini, знайти селектори, зробити пробний скрін |
| Зйомка | скрипти в `record/` | сам дубль: людський темп, паузи, перетягування файлів |
| Озвучка | `voice/tts.mjs` | ElevenLabs пакетом + реальні тривалості реплік |
| Монтаж | Remotion + `ffmpeg` | титри, підписи, склейка, музика |

MCP — це очі й руки на етапі «зрозуміти як». Дубль виробляє скрипт: його можна
перезапустити двадцять разів і повторити на решті уроків.

## Разова підготовка

```bash
cd studio
npm install
node lib/chrome.mjs     # відкриється Chrome — увійдіть у ДЕМО-акаунт Google
npm run check           # перевірка готовності
```

**Чому вхід руками.** Playwright запускає Chrome із прапорцями автоматизації, і Google на
екрані входу відповідає «цей веб-переглядач небезпечний». Перевірка спрацьовує саме в
момент входу, тому логінимось руками у вікні, яке підняв `lib/chrome.mjs`, а скрипти
зйомки під'єднуються до нього по CDP і підхоплюють уже збережену сесію.

Профіль браузера лежить у `%LOCALAPPDATA%\yasno-media\chrome-profile` — поза репозиторієм.
Акаунт **тільки демонстраційний**: у кадрі будуть вигадані звернення громадян, а історія
чатів має бути чистою.

## Зйомка

```bash
npm run smoke        # тестовий дубль без Gemini — перевірити, що конвеєр живий
node record/2-1.mjs  # урок 2.1
```

Під час запису екран зайнятий: ffmpeg пише реальний робочий стіл разом із курсором.
Нічого не чіпати, поки скрипт не завершиться.

**Профіль MCP окремий.** Раніше `.mcp.json` жорстко вказував
`--user-data-dir C:\Users\sasha\AppData\Local\yasno-media\chrome-profile`, щоб MCP і
скрипти зйомки ділили один профіль. Цей рядок прибрано: він містив ім'я конкретного
користувача, а поза Windows зворотний слеш — звичайний символ імені, тож у корені
репозиторію щоразу створювалася тека з буквальною назвою `C:\Users\...` на 9 МБ.

Наслідок: браузер MCP тепер має власний профіль і **не бачить входу в Google**, зробленого
для зйомки. Для розвідки цього досить. Якщо потрібен саме спільний профіль — додайте
`--user-data-dir` із шляхом своєї машини в `.mcp.json` локально (файл у git, тож не
комітьте абсолютний шлях) і закривайте браузер MCP (`browser_close`) перед зйомкою,
інакше профіль буде заблоковано.

## Кадр

Екран — 1920×1080 фізичних пікселів при масштабі Windows 125 %. Це не збіг, а зручність:
gdigrab пише нативні 1080p без ресемплу, а інтерфейс у кадрі виходить крупним — глядач
читає його з телефона. Змінювати масштаб екрана між дублями не можна: поїдуть координати
й розмір шрифту в кадрі.

## Куди лягає результат

- `studio/out/` — дублі, озвучка, архів рендерів, **поза git** (хвилина 1080p ≈ 35 МБ);
- `apps/web/public/media/lessons/<урок>/` — **готова продукція: відео + скріншоти**,
  одна тека на урок, поза git. Разом із `prisma/dev.db` це все, що треба скопіювати,
  щоб платформа на іншій машині була повною;
- `apps/web/public/lessons/<урок>/` — матеріали уроку для завантаження, у git;
- у контенті уроку зберігаються шляхи: `prisma/src/content/lessons-module-*.ts`,
  блок `video('/media/lessons/…')` замість `videoSoon()`, застосовується через
  `pnpm --filter @yasno/db sync-content` (**не** `db:seed` — стирає базу з прогресом).

Перевірити, що все на місці: `npm run media`.

## Правила кадру

- усі дані на екрані вигадані: жодних справжніх ПІБ, адрес, номерів справ;
- кожен крок видно повністю: як файл тягнуть із провідника, як текст копіюють із документа,
  як з'являється відповідь — без стрибків і без «раптом усе готово»;
- прискорювати можна очікування генерації, але не момент перевірки: він має виглядати вагомо;
- у кожній демонстрації видно, що людина **перечитує й виправляє** відповідь ШІ;
- відео ніколи не єдиний носій: те саме дублюється текстом і скріншотами (§1.13 стандарту).
