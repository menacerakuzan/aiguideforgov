# Промо-ролик сервісу ПРО.ШІ

Ролик про **саму платформу**, а не про урок. Третій жанр у курсі — і єдиний,
який не знімається записом екрана.

> Про два інші жанри (урок-інструкція та трейлер курсу) — [`../STANDARD.md`](../STANDARD.md).
> Звідти сюди перенесено рівно один принцип: **дія, результат якої не перевірено,
> вважається такою, що не сталася**. Решта рішень тут інша, і чому — нижче.

---

## Чим це відрізняється від оснастки уроків

| | Уроки (`../record`, `../edit`) | Промо (тут) |
|---|---|---|
| Джерело картинки | запис екрана `ffmpeg gdigrab` | **знімки сторінок** у 2x |
| Рух | той, що був під час зйомки | **авторський**: 2.5D-камера по знімку |
| Кадр | запис 1700×956 + смуга субтитрів 110 px | сторінка на **всі** 1920×1080 |
| Субтитри | вшиті в кадр | **окремим файлом** `.srt` / `.vtt` |
| Тло | темна сцена `#1B1836` | кремовий папір платформи |
| Музика | у трейлері є, бітова | тиха й рівна, на весь хронометраж |
| Звукові ефекти | на кожну дію | лише два натискання курсора |

Три причини, чому промо знімається знімками, а не екраном:

1. **Немає повільних переходів.** Сторінки на `localhost` перемикаються помітно
   довше, ніж на сервері, і в записі це виглядало б як гальмування продукту.
   Тут переходів не існує взагалі: рух малюється в монтажі.
2. **Кадр вільний повністю.** Без смуги субтитрів сторінка займає весь кадр, і
   наліт на неї закінчується рівно 1:1 — без жодного розтягування.
3. **Текст не сиплеться.** Знімок удвічі більший за кадр, а збільшення в
   `PageCam` зроблене властивістю `zoom`, а не `transform: scale`. Це не
   дрібниця: `scale` змушує Chromium спершу растеризувати шар у layout-розмірі
   й лише потім розтягнути його — дрібний текст інтерфейсу перетворюється на
   кашу саме на наїзді, тобто там, де на нього й дивляться.

Оснастка уроків при цьому **не чіпається**: 18 робочих композицій лишаються в
`../edit`, і жодна залежність звідси туди не тягнеться.

## Порядок роботи

```bash
# 1. База: демо-слухачка з живим прогресом
pnpm --filter @proai/db fix-legacy-data     # орган влади, пошти, коди сертифікатів
pnpm --filter @proai/db create-demo         # Марина Гончаренко, 34 з 47 уроків

# 2. Платформа — ПРОДАКШН-збіркою, не dev
pnpm build && pnpm --filter @proai/web start

# 3. Знімання сторінок (headless, екран не займає)
cd studio/promo
npm run capture                 # усі маршрути
npm run capture -- quiz verify  # або лише окремі
npm run crop                    # смуги з довгих сторінок — ОБОВ'ЯЗКОВО після capture

# 4. Озвучка
cd .. && node voice/tts.mjs batch promo/voice/promo.voice.json out/promo/voice
cp out/promo/voice/audio/*.mp3 promo/public/audio/voice/
cp out/promo/voice/voice.json  promo/src/voice.json

# 5. Монтаж і рендер
cd promo
npm run dev                                    # Remotion Studio
npx remotion still src/index.ts SceneCourses out/qa/x.png --frame=120
npm run render
npm run subs                                   # .srt і .vtt

# 6. Версія в архів — і лише окремою командою на платформу
npm run archive -- "чим ця версія відрізняється"
npm run publish -- v04                         # копія в apps/web/public/media/promo/
```

**Архів і викладання розділені навмисно.** Скласти версію в архів безпечно
завжди — це копія в теку поза git. Покласти файл у `apps/web/public/media/`
означає, що його віддаватиме застосунок, і це вже рішення. Поки обидва робила
одна команда, «поки не викладаймо» блокувало й архівування: свіжий рендер
лишався безіменним `promo.mp4`, який наступний рендер просто затирав.

`publish` бере файл із АРХІВУ, а не поточний `out/promo.mp4`: між рендером і
викладанням проєкт устигає перерендеритись, і тоді на платформу поїхало б не
те, що дивилися.

**`npm run crop` після кожного `capture`.** Перезнята сторінка робить свою
смугу застарілою — скрипт зйомки сам нагадує про це рядком наприкінці.

## Що де лежить

```
scripts/capture.mjs      знімання сторінок + вирізки + координати
scripts/crop-bands.mjs   смуги з довгих сторінок (урок — 14 707 px)
scripts/subtitles.mjs    .srt / .vtt із таймінгу озвучки
scripts/music.mjs        музичне тло потрібної довжини (ElevenLabs Music)
scripts/archive.mjs      версія в out/renders/ під наступним номером
scripts/publish.mjs      версія з архіву → apps/web/public/media/promo/
src/lib/PageCam.tsx      2.5D-камера по знімку сторінки (копія зі скіла video-shotcraft)
src/parts/               ноутбук, рамка браузера, курсор, підсвітка, титр, знак
src/scenes/              по сцені; сторінкові зібрані разом у pages.tsx
src/Main.tsx             три таблиці: сцени, репліки, звуки
src/live-layout.json     координати елементів зі СПРАВЖНЬОЇ верстки
src/voice-plan.json      початок кожної репліки (спільний для монтажу й субтитрів)
public/textures/         знімки сторінок і вирізані картки
public/audio/            озвучка й звукові ефекти
out/                     рендери, поза git
```

## Пастки, перевірені на цьому ролику

| Симптом | Причина | Рішення |
|---|---|---|
| Кабінет у кадрі затулено вітальним діалогом | тур показується всім, хто заходить уперше | прапорець `yasno-onboarded` ставиться `addInitScript` до завантаження сторінки |
| Вирізані картки мають кремові кути на фірмовому тлі | `omitBackground` прибирає тло БРАУЗЕРА, а не те, що малює сторінка | перед вирізками `html,body{background:transparent}` |
| Порожній планшет сторінки вийшов діркою | його знімали ПІСЛЯ вмикання прозорості заради вирізок | порожній планшет знімається раніше, тло повертається на місце |
| У тесті підсвічено неправильну відповідь | скрипт клацав «четверту кнопку на сторінці», а нею виявився хибний варіант (кнопками є ще й крапки-лічильник) | вибір за ТЕКСТОМ правильного варіанта |
| Збірка монтажу падає після перезйомки однієї сторінки | `capture` затирав запис сторінки разом із позначкою про смугу | позначка переноситься зі старого запису |
| Увесь ролик не тим шрифтом | у Chromium рендера немає Comfortaa, і `font-family` мовчки зводиться до системного гротеску | `@remotion/google-fonts` у `src/theme.ts`, лише потрібні підмножини й ваги |
| Заміна «ПРО ШІ» → «ПРО.ШІ» у субтитрах не спрацьовує | `\b` у JavaScript визначена через латиницю й біля кирилиці працює навпаки | межі слова не використовуються |
| Рендер з'їдає пам'ять на сторінці уроку | знімок 3840×29414 — 113 млн пікселів на кожен кадр | `crop-bands.mjs` ріже смугу, яка справді в кадрі |
| У кадрі уроку — панель завдань Windows з індикатором «РУС» | ілюстрації самого уроку зняті з реального робочого стола, і знімок сторінки успадкував їх | камера не їде повз цей діапазон: урок розділено на два кадри зі склейкою |
| Чорний прямокутник на чверть кадру посеред кремової сторінки | порожній програвач відео без постера в тілі уроку | той самий обхід — склейка замість подорожі |
| Картка «12 питань», а наступний кадр «ПИТАННЯ 1 З 10» | поріг знімали з одного модуля, а питання з іншого: обидва числа правильні, разом читаються як помилка | обидва кадри беруться з ОДНОГО модуля |
| Чверть ролика — буквальний стоп-кадр | сцени відкривалися двома-трьома секундами нерухомості ДО початку руху | пауза ставиться після того, як щось стало на місце, а не до того |
| Фінал — не пік, а провал енергії | картки починали злітатися аж через секунду після склейки | приліт починається одразу, затримки скорочуються, час польоту теж |
| До 2,5 секунди цифрової тиші посеред ролика | чотири склейки з чотирнадцяти не були озвучені | кожна склейка має свій звук |
| Останній кадр ролика майже порожній | фінал гасили в тло, і обкладинкою в плеєрі ставав порожній папір | згасання прибрано, ролик закінчується на знаку |
| Рамка підсвітки ховається під карткою | ділянку підсвічували без поля | `pad` у `Spotlight`, підібраний для кожного кадру окремо |
| Світло горить, коли предмет уже поїхав із кадру | підсвітка гасла разом зі сценою, а не зі своїм предметом | `life` у `Spotlight` |
| Головний герой заставки збирається за 0,8 с | знак успадкував темп підпису в кутку уроку | `pace` у `BrandMark` розтягує всю дугу, зберігаючи співвідношення тактів |

## Перевірка перед здачею

1. **Покадрові стопкадри кожної сцени** (`remotion still`) — до повного рендера.
2. **Чорні кадри по всьому хронометражу**:
   `ffmpeg -i out/promo-vNN.mp4 -vf "signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=yavg.txt" -f null -`,
   шукати `YAVG < 120`. Особлива увага — стик нальоту, де корпус ноутбука
   змінюється на повнокадрову сторінку.
3. **Гучність** вікнами по 5 с (`-af volumedetect`): рівно, без провалів.
4. **Читабельність** дрібного тексту на кадрах максимального наїзду.
5. **Незалежне приймання** окремим агентом із чистим контекстом — автор до
   власної роботи упереджений.
