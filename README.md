# ПРО.ШІ

Платформа безпечного використання штучного інтелекту для державної служби.
Майбутній домен — `proai.od.gov.ua`.

Дизайн-мова — приглушений claymorphism, світлофор даних як сигнатурна концепція.
Канонічний дизайн-референс (5 статичних HTML-прототипів) лежить у `docs/design-reference/`.

## Стек

| Шар | Технологія |
|---|---|
| Frontend | Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS v4 · Motion · TanStack Query · Zod · React Hook Form |
| Backend | Next.js Route Handlers, бізнес-логіка винесена в `services/*` |
| База даних | SQLite |
| ORM | Prisma |
| Auth | Better Auth (email/password) + власний RBAC на дві ролі |
| Кеш / файли / пошта | Локальні реалізації (`services/infra`) за інтерфейсами Storage/Cache/Mailer — під заміну на S3/Redis/Resend без зміни викликів |

```

  learning/             Курси, уроки, прогрес, тести, фінальна атестація
  prompts/              Бібліотека промптів, обране, лічильник копіювань
  certificates/         Видача / публічна перевірка / відкликання сертифікатів
```

## RBAC — дві ролі

`LEARNER` вчиться. `ADMIN` бачить і керує всім: користувачами, контентом,
сертифікатами, статистикою. Проміжних ролей немає — перевірка зводиться до
`isAdmin(role)` у `services/auth/src/rbac.ts`.

Змінити роль можна лише через `PATCH /api/users` і лише адміністратором.
Зняти адміністратора із себе не можна, як і прибрати останнього адміністратора
платформи — інакше розділ адміністрування став би недосяжним для всіх.

Роль **не приймається від клієнта на реєстрації**: у Better Auth поле `role`
оголошено з `input: false`, тож підставити собі `ADMIN` у тілі запиту неможливо.

## Швидкий старт

```bash
pnpm install

cp .env.example .env
# Файл один — у корені. Скрипти apps/web і prisma читають саме його.

# Згенеруйте власний секрет:
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"

# Задайте ADMIN_EMAIL і ADMIN_PASSWORD — без них seed не піде.
# Пароль: мінімум 12 символів. Згенерувати:
node -e "console.log(require('crypto').randomBytes(18).toString('base64url'))"

pnpm db:migrate      # створює SQLite-базу + застосовує схему
pnpm db:seed         # контент курсу + ЄДИНИЙ адміністратор із .env
pnpm db:sync-library # трофеї бібліотеки (seed їх не генерує)
pnpm dev             # http://localhost:3000
```

Правки контенту без стирання бази — `db:seed` чистить її повністю, тому для
щоденної роботи потрібні не він, а ці два:

```bash
pnpm db:sync-content # тексти уроків з prisma/src/content/lessons-module-*.ts
pnpm db:sync-quiz    # тести модулів і атестація з prisma/src/content/quizzes.ts
pnpm db:sync-courses # назви, описи й відкритість курсів з prisma/src/sync-courses.ts
```

Усі три оновлюють лише контент: користувачі, сесії, прогрес і спроби лишаються.
Перед `db:sync-quiz` варто прогнати `pnpm --filter @proai/db audit-quiz` — він
ловить перекос позицій правильної відповіді й підказку довжиною варіанта.

### Зміна схеми бази

Структуру (нові поля, таблиці, індекси) міняють у `prisma/schema.prisma`, а далі
створюють міграцію — ім'я передається аргументом:

```bash
pnpm db:migrate --name add_longest_streak
```

Без `--name` Prisma спитає ім'я інтерактивно. Prisma сама порівняє схему з базою,
запише SQL у `prisma/migrations/<час>_<ім'я>/migration.sql` і застосує його; папку
міграції **обов'язково комітимо** — саме вона, а не `schema.prisma`, є джерелом
істини для продакшну.

Prisma Client після зміни схеми перегенерувати обов'язково, інакше збірка впаде
на перевірці типів. `migrate dev` робить це сам, а `migrate deploy` на сервері —
ні (генератори він не запускає навмисно). Щоб про це не треба було пам'ятати,
`build`, `typecheck`, `lint` і `test` у `turbo.json` залежать від
`@proai/db#generate` — генерація відбувається сама. Викликати руками —
`pnpm db:generate`.

Перевірити, що схема й міграції не розійшлися (корисно перед релізом):

```bash
cd prisma && npx dotenv -e ../.env -- prisma migrate status
npx prisma migrate diff --from-migrations ./migrations \
  --to-schema-datamodel ./schema.prisma \
  --shadow-database-url "file:/tmp/shadow.db" --exit-code
```

Друга команда має сказати «No difference detected» і завершитись кодом 0.

> Запускайте Prisma **лише через `pnpm`-скрипти або з каталогу `prisma/`**.
> `npx prisma` із кореня репозиторію не знаходить локальний пакет і завантажує
> свіжу мажорну версію з реєстру — тобто виконає команду не тією Prisma, що
> в проєкті.

> У продакшні застосунок **не стартує** з шаблонним або відсутнім
> `BETTER_AUTH_SECRET` — перевірка в `services/infra/src/env.ts`. Це навмисно:
> без неї Better Auth мовчки взяв би запасний ключ, і сесії підписувалися б
> передбачуваним секретом.

Перевірка якості:

```bash
pnpm typecheck   # tsc --noEmit по всіх пакетах
pnpm lint
pnpm test        # vitest: сертифікати, санітизація HTML, схеми реєстрації, серія днів
pnpm build
```

## Акаунти

Платформа розгортається **порожньою**: жодних демо-слухачів, жодних паролів у
git. Є рівно один адміністратор — той, що заданий у `.env`:

```ini
ADMIN_EMAIL="admin@ваш-домен"
ADMIN_PASSWORD="<довгий випадковий>"
```

Слухачі реєструються самі через `/register`. Прогрес, сертифікати й статистика
починаються з нуля — у списку користувачів адмінки видно реальних людей, а не
вигаданих.

Створити адміністратора або скинути йому пароль на **вже робочій** базі, нічого
не стираючи:

```bash
pnpm db:create-admin
```

Це єдиний спосіб повернути доступ, якщо пароль адміністратора загублено:
автоматичного відновлення в платформі немає (немає поштового провайдера), а
слухачам сторінка `/forgot-password` пропонує написати в підтримку.

## Модель курсу

Джерело істини для структури — [`plan.md`](plan.md) (архітектура) і [`lessons.md`](lessons.md)
(поурочний опис). Seed зібраний строго за ними.

На платформі **два курси**: базовий самодостатній і прикладний, який поки закрито.

| Курс | Розділів | Стан |
|---|---|---|
| **ШІ в публічній службі** (базовий) | 1 «Основи ШІ», 5 модулів | ✅ повний контент (47 уроків), тести, атестація, сертифікат |
| **Продвинутий курс** | 7 прикладних розділів, 44 модулі | 🔒 закритий (`Course.comingSoon`), усередині заглушки |

Прикладний курс лишається в базі й редагується в CMS, але слухачам недоступний:
картка на `/courses` не веде всередину, а `getModuleBySlug`, `getLesson`,
`completeLesson` і `/api/courses/select` відмовляють і на прямий запит. Відкрити —
змінити `comingSoon` на `false` у `prisma/src/sync-courses.ts` і виконати
`pnpm db:sync-courses`.

Розділи прикладного курсу: Документи і тексти (7 модулів) · Таблиці та дані (6) ·
Щоденні задачі (5) · Презентації та візуал (6) · Аудіо (5) · Зображення та відео (7) ·
Пошук, аналіз, переклад (8).

Розділ «Основи ШІ» — головний, проходиться першим: **1** знайомство й перший інструмент →
**2** одразу практика (користь до правил) → **3** безпека → **4** промптинг → **5** перевірка результату.

Модуль 3 «Безпека та відповідальність» — ключовий (`isKey: true`, прохідний бал **90%**
замість стандартних 75%). Без нього сертифікат не видається.

### Послідовність проходження

**Модулі — по черзі, уроки всередині модуля — вільно.** Модуль N+1 відкривається,
коли N завершено повністю (усі уроки + зарахований тест), — саме це не дає
перестрибнути модуль «Безпека». Уроки всередині модуля навмисно не замикаються:
наступний підсвічено, дальші приглушені, але відкрити можна будь-який — вони
сусіди по одній темі, а жорсткий замок перетворює людину, яка застрягла на
одному уроці, на людину, яка пішла.

Два винятки, без яких правило шкодило б: **пройдений модуль не закривається
ніколи** (на цьому тримається бібліотека-трофеї — до матеріалу повертаються) і
**розпочатий модуль не закривається заднім числом** (інакше слухачі посеред
курсу назавтра побачили б закритим те, що проходили вчора).

Правило живе в `computeModuleLocks` / `getModuleLock`
(`services/learning/src/lib/completion.ts`) і покрите тестами; сторінки лише
показують результат. Перевіряється й на сервері: `getLesson` і `completeLesson`
відмовляють запиту повз інтерфейс.

**Інструменти вводяться поступово**, не всі одразу: у Розділі 1 тільки Gemini (основний)
і ChatGPT. Далі — Claude (розд. 2), Gamma і Canva (5), ElevenLabs (6), Ideogram (7),
Perplexity, NotebookLM і DeepL (8). Модулі-знайомства позначені полем `tool` у seed:
кожен обов'язково містить блок про безкоштовні ліміти сервісу.

Фінальна атестація: 30 питань, прохідний **80%** і окремо **90%** за питання з міткою
`isSecurity`. Допуск перевіряється на сервері, а не лише кнопкою на сторінці.
Курс вважається пройденим, коли відмічено прогрес по кожному уроку **і**
(якщо в модуля є тест) останню спробу зараховано. Сертифікат видається автоматично
(`services/learning` → `services/certificates`).

## Безпека

Коротко про рішення, які легко зламати необережною правкою:

- **CSP із nonce** формується в `apps/web/src/middleware.ts` і мусить лишатися
  саме там: nonce різний на кожну відповідь, тож у `next.config.ts` його
  віддати неможливо. Інлайн-скрипт теми в `app/layout.tsx` отримує цей nonce
  явно — без нього CSP заблокує його, і сторінка почне блимати світлою темою.
- **Санітизація HTML** (`services/infra/src/html.ts`) застосовується на **записі**:
  адмінське API, `seed.ts`, `sync-content.ts`. Контент уроків рендериться через
  `dangerouslySetInnerHTML`, іншого фільтра між базою і слухачем немає.
  Якщо зʼявиться новий шлях запису контенту — він теж мусить пройти через
  `sanitizeLessonBlocks` / `sanitizeRichHtml`.
- **Обмеження частоти** на `/sign-in/email`, `/sign-up/email`, `/forget-password`
  налаштовано в `services/auth/src/instance.ts`. Без нього форма входу — стенд
  для перебору паролів.
- **Публічна перевірка сертифіката** віддає `PublicCertificate` (без `id` і
  `userId`). Не повертайте туди повний рядок таблиці.
- **middleware не перевіряє автентичність** сесії — лише наявність куки, бо
  SQLite несумісний з Edge runtime. Справжня перевірка живе в layout'ах
  (`getCurrentUser`) і в кожному API-роуті (`requireCurrentUser`).

## Відомі нюанси

- `better-call` (внутрішня залежність `better-auth`) хоче `zod@^4`, у проєкті `zod@^3.24` —
  peer-warning при встановленні, на роботу не впливає (typecheck/build/рантайм чисті).
- `pnpm-workspace.yaml` вимикає build-скрипти пакетів prisma (`allowBuilds`), тому `pnpm install`
  сам по собі Prisma Client НЕ генерує. Щоб це не ловилося аж на першому запуску помилкою
  «does not provide an export named 'PrismaClient'», у `prisma/package.json` є власний
  `postinstall: prisma generate` — він виконується, бо стосується workspace-пакета, а не
  зовнішньої залежності. `prisma generate` не потребує `DATABASE_URL`, тож на свіжому клоні
  без `.env` установлення не падає.
- `@prisma/client` додано прямою залежністю `apps/web` (не лише через `@proai/db`) — інакше
  pnpm-ізоляція не дає Next.js `serverExternalPackages` знайти вже згенерований рушій під час
  бандлингу.
- `sanitize-html` і `@react-pdf/renderer` перелічені в `serverExternalPackages`: обидва
  тягнуть CJS/нативні ресурси, які не переживають трасування бандлером.
- `node_modules` **не переносяться між ОС**. Каталог, встановлений на Linux, на Windows
  дає биті симлінки й `Cannot find module` на будь-якому бінарнику. Після зміни машини —
  `pnpm install` заново.
